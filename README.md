# Snail.Toolkit.Nomad

Typed client for the [HashiCorp Nomad HTTP API](https://developer.hashicorp.com/nomad/api-docs) for .NET 10, with Microsoft-only dependencies:

- `INomadClient` — parse HCL2 jobs with variables, register, read, list, scale and stop jobs; read allocations, evaluations, client nodes and task logs;
- `HclVariables` — renders job variables in the var-file syntax the parse endpoint expects;
- a health check that asks the agent for its version and the cluster for its leader, under a probe budget of its own.

Everything goes through one `HttpClient` from `IHttpClientFactory`; the ACL token travels as `X-Nomad-Token`, namespace and region as query parameters of every call.

| Namespace | Contents |
|---|---|
| `Snail.Toolkit.Nomad` | `INomadClient` (and its halves `INomadStatus`, `INomadJobs`, `INomadScheduling`, `INomadNodes`, `INomadLogs`), `NomadClient`, `NomadOptions`, `NomadException`, `HclVariables`, `JobEdits` |
| `Snail.Toolkit.Nomad.Models` | `NomadJob`, `JobStub`, `JobSummary`, `TaskGroupSummary`, `JobRegistration`, `Allocation`, `Evaluation`, `NodeStub`, `NomadAgent`, `LogType`, `NomadPaging`, `NomadPage<T>` |
| `Snail.Toolkit.Nomad.Extensions` | `AddNomad`, `AddNomadHealthCheck` |
| `Snail.Toolkit.Nomad.Health` | `NomadHealthCheck` |

### Configuration

```json
{
  "Nomad": {
    "Address": "http://localhost:4646",
    "Token": null,
    "Namespace": null,
    "Region": null,
    "Timeout": "00:00:30",
    "WatchWait": "00:00:20"
  }
}
```

`Address` is required and has no default — a missing one fails validation at start rather than quietly meaning localhost. `Token` is sent when set; `Namespace` and `Region` scope every request when set and fall back to the server defaults otherwise. `WatchWait` is how long a blocking query is held open and has to stay under `Timeout`.

### Registration

```c#
using Snail.Toolkit.Nomad.Extensions;

builder.Services
    .AddNomad(builder.Configuration)   // INomadClient over IHttpClientFactory
    .AddNomadHealthCheck();            // health check "nomad", 5 s probe budget

// or in code
builder.Services.AddNomad(options => options.Address = "http://nomad.service:4646");
```

Each half of the contract is registered on its own, so a log viewer injects `INomadLogs` rather than all of Nomad.

No resilience handler is added. A blanket retry would resend `POST /v1/jobs` and register a job twice — reads and a stop are safe to retry, a registration only when it carries an index. Attach your own through the second argument:

```c#
builder.Services.AddNomad(builder.Configuration, client => client.AddStandardResilienceHandler());
```

### Jobs

A job written in HCL2 with `variable` blocks is parsed by the server, so no HCL is generated by hand. The variables are passed as a var-file string — `HclVariables.Render` produces it from a dictionary, ordered by name so the same variables always produce the same text. Names are checked as HCL identifiers, and values carrying `${` or `%{` are escaped rather than left for the parser to execute:

```c#
var hcl = await File.ReadAllTextAsync("deploy/nomad/mcp-NAME.nomad.hcl");

var job = await nomad.ParseJobAsync(
    hcl.Replace("mcp-NAME", "mcp-search"),           // HCL2 has no variables in job ids
    HclVariables.Render(new Dictionary<string, object?>
    {
        ["name"] = "search",
        ["image"] = "snail/mcp-search:latest",
        ["port"] = 8803,
        ["nodes"] = new[] { "http://gpu-1:11434" }   // lists and maps nest
    }));

job.WithGroupCount("server", 2)                      // by name, not by position
   .WithMeta("deployed-by", "dashboard");

var registration = await nomad.RegisterJobAsync(job); // { EvalId, JobModifyIndex, Warnings }
```

The parsed job stays a `JsonObject` on purpose: a registration replaces the job whole, and a typed model covering only the fields this platform reads would drop every other block on the way back. `JobEdits` reaches the few places worth editing by name instead.

Where two deployers can race, register against the index the job was read at:

```c#
var current = await nomad.GetJobAsync("mcp-search");
var registration = await nomad.RegisterJobAsync(job, expectedModifyIndex: registration.JobModifyIndex);
if (registration is null)
    // someone else changed it in between — read it again and decide
```

Reading and controlling:

```c#
var current = await nomad.GetJobAsync("mcp-search");           // null when unknown
var stubs   = await nomad.ListJobsAsync(prefix: "mcp-");       // with JobSummary counts per group
var summary = await nomad.GetJobSummaryAsync("mcp-search");    // Queued / Running / Failed ...
var allocs  = await nomad.ListAllocationsAsync("mcp-search");  // newest first
var evals   = await nomad.ListEvaluationsAsync("mcp-search");  // blocked ones name the groups that cannot be placed

await nomad.ScaleJobAsync("mcp-search", taskGroup: "server", count: 2, message: "dashboard");
await nomad.StopJobAsync("mcp-search", purge: true);           // null when unknown
```

`ScaleJobAsync` throws `NomadException` with Nomad's own text (`job scaling blocked due to active deployment`) while the previous deployment is still running — register the job again with a new count instead, or wait.

### Watching

Nomad holds a request open until something changes, so following a job costs one idle connection instead of a poll loop:

```c#
await foreach (var job in nomad.WatchJobAsync("mcp-search", cancellationToken))
    Console.WriteLine($"{job.Status}: {job.DesiredCount} desired");

await foreach (var allocations in nomad.WatchAllocationsAsync("mcp-search", cancellationToken))
    Console.WriteLine($"{allocations.Count(allocation => allocation.IsRunning)} running");
```

The sequence yields the current state first, then only on a real change, and ends when the job is purged.

### Paging

The plain list calls read everything. On a large cluster take a page at a time:

```c#
var paging = new NomadPaging(PageSize: 100);
do
{
    var page = await nomad.ListJobsAsync(paging, prefix: "mcp-");
    Handle(page.Items);
    paging = paging with { Token = page.NextToken };
}
while (paging.Token is not null);
```

### Allocations, nodes, logs

```c#
var nodes = await nomad.ListNodesAsync();                          // IsReady = ready, not draining, eligible
var text  = await nomad.ReadLogsAsync(alloc.Id, task: "mcp", LogType.Stderr, tailBytes: 4096);
```

`ReadLogsAsync` returns the tail of the stream as plain text, and an empty string when the allocation is gone or has written nothing yet. A client node that cannot be reached throws instead: a log viewer has to tell "this task said nothing" from "nobody could be asked". `tailBytes` is capped at `NomadClient.MaxTailBytes` (1 MiB).

### Errors

Every call that Nomad answers with an error status throws `NomadException`, carrying the status, Nomad's plain-text body (cut at `NomadException.BodyLimit`), and the method and address of the failed call.

Reads addressed at one object by its id — `GetJobAsync`, `GetJobSummaryAsync`, `StopJobAsync` — return `null` when Nomad does not know it, and the lists hanging off a job id are empty. A list endpoint takes no id, so `ListJobsAsync` and `ListNodesAsync` treat a 404 as the error it is: an address that is not a Nomad agent must not read as an empty cluster.

The models say what Nomad always sends. A body that omits a required field, or sends `null` where the type says it cannot be, fails the read instead of arriving as a `null` that a computed property later dereferences.

### Tests

Unit tests run everywhere. Integration tests start a server-only `hashicorp/nomad` agent through Testcontainers (jobs are accepted and stay queued without client nodes, which exercises the whole job API) and are skipped when no Docker daemon is reachable.
