## Snail.Toolkit.Nomad

Typed client for the [HashiCorp Nomad HTTP API](https://developer.hashicorp.com/nomad/api-docs) for .NET 10, with Microsoft-only dependencies:

- `INomadClient` — parse HCL2 jobs with variables, register, read, list, scale and stop jobs; read allocations, evaluations, client nodes and task logs;
- `HclVariables` — renders job variables in the var-file syntax the parse endpoint expects;
- a health check that asks the agent for its version and the cluster for its leader.

Everything goes through one `HttpClient` from `IHttpClientFactory`; the ACL token travels as `X-Nomad-Token`, namespace and region as query parameters of every call.

| Namespace | Contents |
|---|---|
| `Snail.Toolkit.Nomad` | `INomadClient`, `NomadClient`, `NomadOptions`, `NomadException`, `HclVariables` |
| `Snail.Toolkit.Nomad.Models` | `NomadJob`, `JobStub`, `JobSummary`, `TaskGroupSummary`, `JobRegistration`, `Allocation`, `Evaluation`, `NodeStub`, `NomadAgent`, `LogType` |
| `Snail.Toolkit.Nomad.Extensions` | `AddNomad`, `AddNomadHealthCheck` |
| `Snail.Toolkit.Nomad.Health` | `NomadHealthCheck` |

### Configuration

```json
{
  "Nomad": {
    "Address": "http://localhost:4646",
    "Token": null,
    "Namespace": null,
    "Region": null,
    "Timeout": "00:00:30"
  }
}
```

`Address` is required. `Token` is sent when set; `Namespace` and `Region` scope every request when set and fall back to the server defaults otherwise.

### Registration

```c#
using Snail.Toolkit.Nomad.Extensions;

builder.Services
    .AddNomad(builder.Configuration)   // INomadClient over IHttpClientFactory
    .AddNomadHealthCheck();            // health check "nomad"

// or in code
builder.Services.AddNomad(options => options.Address = "http://nomad.service:4646");
```

### Jobs

A job written in HCL2 with `variable` blocks is parsed by the server, so no HCL is generated by hand. The variables are passed as a var-file string — `HclVariables.Render` produces it from a dictionary:

```c#
var hcl = await File.ReadAllTextAsync("deploy/nomad/mcp-NAME.nomad.hcl");

var job = await nomad.ParseJobAsync(
    hcl.Replace("mcp-NAME", "mcp-search"),           // HCL2 has no variables in job ids
    HclVariables.Render(new Dictionary<string, object?>
    {
        ["name"] = "search",
        ["image"] = "snail/mcp-search:latest",
        ["port"] = 8803,
        ["nodes"] = new[] { "http://gpu-1:11434" }   // lists and maps nest
    }));

job["TaskGroups"]![0]!["Count"] = 2;                 // the parsed job is a JsonObject you may edit

var registration = await nomad.RegisterJobAsync(job); // { EvalId, JobModifyIndex, Warnings }
```

Reading and controlling:

```c#
var current = await nomad.GetJobAsync("mcp-search");           // null when unknown
var stubs   = await nomad.ListJobsAsync(prefix: "mcp-");       // with JobSummary counts per group
var summary = await nomad.GetJobSummaryAsync("mcp-search");    // Queued / Running / Failed ...
var allocs  = await nomad.ListAllocationsAsync("mcp-search");  // newest first
var evals   = await nomad.ListEvaluationsAsync("mcp-search");  // blocked ones name the groups that cannot be placed

await nomad.ScaleJobAsync("mcp-search", taskGroup: "server", count: 2, message: "dashboard");
await nomad.StopJobAsync("mcp-search", purge: true);           // null when unknown
```

`ScaleJobAsync` throws `NomadException` with Nomad's own text (`job scaling blocked due to active deployment`) while the previous deployment is still running — register the job again with a new count instead, or wait.

### Allocations, nodes, logs

```c#
var nodes = await nomad.ListNodesAsync();                          // IsReady = ready, not draining, eligible
var text  = await nomad.ReadLogsAsync(alloc.Id, task: "mcp", LogType.Stderr, tailBytes: 4096);
```

`ReadLogsAsync` returns the tail of the stream as plain text and an empty string when the allocation is gone or its client cannot be reached — a log viewer should not fail on either.

### Errors

Every call that Nomad answers with an error status throws `NomadException` carrying the status and Nomad's plain-text body. Reads of a missing object (`GetJobAsync`, `GetJobSummaryAsync`, `StopJobAsync`) return `null` instead; lists of a missing job are empty.

### Tests

Unit tests run everywhere. Integration tests start a server-only `hashicorp/nomad` agent through Testcontainers (jobs are accepted and stay queued without client nodes, which exercises the whole job API) and are skipped when no Docker daemon is reachable.
